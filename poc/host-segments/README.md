# SPS-737 · передача fMP4 через DataChannel

Изолированный **локальный** прототип Spectemus Simul. Он проверяет альтернативу
`video → captureStream → live encoder`: совместимые сжатые данные читаются
небольшими блоками, передаются через прямой WebRTC DataChannel и декодируются
браузером гостя. Рабочие LAN-приложения и старый public runtime не меняются.

## Что нужно

Node.js и установленные зависимости репозитория, Chrome/Edge, FFmpeg/ffprobe
в PATH (или явные пути). Источник — H.264 8-bit `yuv420p` и AAC-LC, либо без
аудио. MKV с такими дорожками подходит; HEVC/DTS и другие кодеки этот PoC
отклоняет, а не запускает скрытое перекодирование.

## Запуск

Из корня проекта:

```bash
pnpm segment:poc -- --input "/path/to/movie.mkv"
```

Если инструменты не в PATH, добавьте `--ffmpeg <binary>` и `--ffprobe <binary>`.
Оригинал не меняется. FFmpeg создаёт временную fragmented MP4-копию через
`-c copy`, без видеоэнкодера. Команда выдаёт разные capability-ссылки для host
и guest. Это намеренный локальный вывод приглашений, не серверный access log;
не публикуйте ссылки. Откройте их в двух окнах Chrome/Edge и нажмите
«Подключиться» в обоих. При необходимости разрешите гостевое воспроизведение,
затем управляйте «Играть»/«Пауза» у host-а. «Остановить» или закрытие одного
окна завершает пару; для нового сеанса перезапустите команду. `Ctrl+C` закрывает
сервер и удаляет временную копию. Force-kill может оставить каталог
`spectemus-segments-*` в системном temp: аварийный sweep не входит в PoC.

Гость получает сжатое содержимое фильма и технически может его сохранить.
Полный файл автоматически не скачивается, но защиты от копирования/записи
здесь нет. Приглашать нужно доверенного человека; обещания DRM нет.

Сервер слушает **только `127.0.0.1`**. Эта ссылка не работает на другом
компьютере; флага открытия LAN/Internet намеренно нет. Нельзя превращать этот
HTTP-прототип в публичный сервер пробросом портов.

## Ограничение нагрузки

- Один host и один guest. Signaling не принимает media bytes.
- Guest не имеет HTTP-доступа к файлу. Host читает только запрошенный блок до
  64 KiB и отправляет его гостю; один запрос одновременно.
- Следующий блок запрашивается после завершения MSE append. Целевой запас —
  12 секунд; возможен выход за цель на один блок, особенно у видео с малым
  bitrate. Старые MSE-диапазоны удаляются при последующем append (остаётся
  примерно 3 секунды позади). Это backpressure и ограничение JS-очереди,
  **не** доказанный предел общей RAM браузера.
- Нет live video encoder, simulcast, отдельной подготовленной копии на каждого
  гостя и фонового транскода.
  Оба браузера всё равно расходуют ресурсы на декодирование, а хост — на
  чтение/передачу и первоначальный remux.
- Диагностика показывает байты, запас, decoded frames и состояние ICE без
  адресов, ключей и файловых путей. CPU/GPU/полная RAM и поведение длинного
  фильма ещё требуют физического измерения.

## Проверки

```bash
pnpm test:media-poc
pnpm --dir e2e exec playwright install chromium
pnpm segment:poc:smoke
```

Для уже установленного Chrome: `PLAYWRIGHT_CHANNEL=chrome pnpm segment:poc:smoke`
(в PowerShell сначала `$env:PLAYWRIGHT_CHANNEL="chrome"`). Smoke генерирует
24-секундный синтетический MKV, remux-ит его, запускает два независимых browser
context и проверяет ограничение предзагрузки, первый кадр, паузу, завершение
и остановку пары. Для автоматизации используются autoplay/loopback флаги и
**только в smoke** ICE host candidates заменяются на `127.0.0.1` перед
передачей в браузерный WebRTC. DTLS/SCTP/DataChannel и декодирование остаются
настоящими; это test-only сетевой адаптер для медиапроверки, не доказательство
native ICE или NAT. PoC UI SDP не изменяет. Для проверки без адаптера задайте
`POC_NATIVE_ICE=true`. В текущей локальной среде native UDP/ICE не прошёл:
UDP доступен на loopback, но не доставлялся на собственные LAN-адреса.
Ни этот запуск, ни успешный адаптированный smoke не являются evidence другой
сети или тестом слышимого звука.

Перемотка, восстановление соединения, чат/голос, несколько гостей, QR,
автоматическое NAT traversal, HTTPS и internet security protocol — вне этого
среза. Их нельзя считать готовыми из-за успешного loopback smoke.
