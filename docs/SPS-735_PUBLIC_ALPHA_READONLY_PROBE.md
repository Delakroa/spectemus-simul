# SPS-735: безопасная проверка публичного стенда

## Цель и граница

Перед первым просмотром из разных сетей оператору нужна отдельная проверка
Internet-стенда. Исторический `beta:smoke` использует `/api/v1`, создаёт LAN-комнату
и не подходит для публичного режима. Этот тикет добавляет только **читающие**
запросы и проверку TLS. Он не создаёт account или комнату, не отправляет
учётные данные и не объявляет медиапоток рабочим.

## Критерии готовности

1. Команда принимает только три публичных DNS-имени. Защищённый env-файл
   остаётся на VM и проверяется отдельным `staging:preflight --public`.
2. Снаружи проверяется доверенный TLS для `app`, `rtc`, `turn`. На `app`
   дополнительно проверяются HTML-вход и защитные заголовки.
3. `/api/v1/rooms`, `/actuator/health`, `/operator/`, `/gateway-health`
   остаются 404; `/api/v2/account` без cookie отвечает структурированным
   `401 ACCOUNT_REQUIRED`. Redirect и HTML вместо API-ошибки — провал.
4. У сетевых операций есть короткий таймаут. Ошибки не выводят тело ответа,
   credentials или содержимое env-файла. Unit-тесты покрывают отказные пути.

## Запуск и проверка

После запуска opt-in Internet staging из внешней сети:

```bash
pnpm staging:public:probe -- \
  --app-domain app.<domain> \
  --rtc-domain rtc.<domain> \
  --turn-domain turn.<domain>
```

Локальная проверка реализации: `pnpm test:staging` и `pnpm check`.

## Ограничения и следующий gate

TLS handshake `rtc` и `turn` подтверждает сертификат и доступность порта, **не**
подтверждает WSS-сигналинг, ICE, TURN relay или просмотр фильма. Для них нужны
реальная VM, DNS, две разные сети и физический прогон. Команда не заменяет
проверку приватности логов на VM и не запускается автоматически в CI против
чужого адреса. Rollback: удалить команду; сервер и данные она не меняет.

REST/WebSocket contracts — N/A: новые product endpoints не добавляются.
