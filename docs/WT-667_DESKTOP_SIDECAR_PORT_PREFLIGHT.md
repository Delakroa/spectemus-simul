# WT-667 — быстрый preflight портов desktop sidecar

## Проблема

Gateway умеет перейти с занятого `8088` на свободный порт, но backend и
LiveKit используют связанную фиксированную схему: backend `8080`, LiveKit TCP
`7880`/`7881` и UDP `50000–50100`. При занятом порте второй запуск приложения
или локальный Docker/dev stack раньше приводил к долгому ожиданию health check.

## Решение

Перед запуском любых sidecar desktop host проверяет возможность bind для всех
этих TCP- и UDP-портов. Если один занят, ни backend, ни LiveKit не запускаются,
а пользователь сразу получает название сервиса, номер порта и безопасное
действие: остановить другую копию приложения или Docker/dev stack, затем
запустить host заново.

Автоматически менять порты LiveKit нельзя: это согласованная TCP/UDP media
схема, связанная с token URL и Windows firewall. Такой fallback был бы менее
предсказуемым, чем явная ошибка.

## Проверка

```bash
pnpm --dir desktop test
```

Регрессионный тест подтверждает, что при конфликте порта sidecar не spawn-ятся.
