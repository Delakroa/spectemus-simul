# WT-675 — остановка desktop host и запуск видео у гостя

## Цель

Закрыть две проблемы, найденные в реальной LAN-проверке Mac + Windows:

- после закрытия приложения backend мог оставаться на `127.0.0.1:8080` и
  блокировать следующий запуск host-а;
- guest получал video track, но браузер мог отклонить его autoplay, хотя звук
  фильма передаётся отдельной аудиодорожкой.

## Реализовано

- `DesktopSupervisor` посылает sidecar-у `SIGTERM`, при необходимости
  `SIGKILL`, и ждёт событие `exit`. Если процесс не подтвердил завершение,
  cleanup помечается неуспешным вместо ложного сообщения об остановке.
- Remote `<video>` всегда muted: это не отключает звук фильма, потому что за
  громкость отвечает отдельный remote `<audio>` и существующие controls.
  Такое видео разрешено браузерам запускать автоматически.
- Если браузер всё же требует пользовательского действия, гость видит понятную
  кнопку «Включить видео», а не сырой текст browser exception.

## Проверка

```bash
pnpm --filter @spectemus-simul/frontend test -- remote-playback.test.ts
pnpm --dir desktop test
pnpm check
```

## Граница совместимости

Эта задача исправляет запуск доставленного remote video, но не делает любой
локальный исходный файл универсальным. MKV с HEVC 10-bit и FLAC остаётся
экспериментальным путём: источник сначала должен декодироваться у host-а, а
кроссплатформенную гарантию дадут только будущая нормализация/транскодирование
и отдельная проверка на реальных устройствах.
