# SPS-696 — политика публикации изменений агентом

## Проблема

После сокращения `AGENTS.md` появилось правило, что коммит и push всегда делает
только владелец репозитория. Оно расходилось с согласованным рабочим циклом
проекта: владелец может явно поручить агенту довести задачу до PR, зелёного CI и
merge.

## Правило

- Без явного разрешения владельца агент не коммитит, не делает push и не создаёт
  внешние изменения: готовая работа остаётся в рабочем дереве.
- Явное разрешение в текущей задаче даёт агенту право коммитить в task-ветку,
  отправлять её, вести PR и сливать зелёный PR.
- Прямой push в `main` остаётся запрещённым при любых условиях. Изменения в
  `main` попадают только через pull request.

## Граница

Это правило описывает авторизацию публикации, а не отменяет проверку состава
коммита, локальные тесты, CI или review. Оно также не переносится автоматически
на будущие задачи без нового разрешения владельца.
