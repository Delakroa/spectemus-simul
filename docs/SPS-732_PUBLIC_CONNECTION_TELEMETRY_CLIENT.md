# SPS-732 — отправка событий соединения из Internet-комнаты

## Цель

Подключить browser и desktop к серверному контракту SPS-731, чтобы при
межсетевых испытаниях видеть агрегированные сбои соединения. Отправка
добровольная: в каждой открытой Internet-комнате она выключена по умолчанию.

## Поведение

- В свёрнутой диагностике пользователь может включить отправку агрегированных
  событий. Согласие действует только пока открыта эта комната: после выхода
  или перезагрузки страницы его надо дать заново. Выключение прекращает новые
  отправки; уже начатый запрос может завершиться.
- LiveKit-состояния дают `CONNECTED`, `RECONNECTING`, `RECONNECTED`,
  `DISCONNECTED`, а локальная оценка качества — `QUALITY_POOR` и
  `QUALITY_LOST`. Повторяющиеся одинаковые состояния не создают дубликатов.
  Ошибка первого подключения не считается разрывом уже установленной связи.
- Browser использует cookie и `/api/v2`; desktop renderer передаёт в IPC только
  UUID комнаты и тип события. Main-процесс проверяет оба поля, добавляет
  сохранённый device Bearer и использует заранее настроенный HTTPS origin.
  Подмена URL или добавление произвольного поля через IPC отклоняются.
- В обоих клиентах запрос ограничен пятью секундами. Сбой отправки не влияет на
  фильм, состояние комнаты или кнопку переподключения. Если старая версия
  desktop не имеет нового IPC-метода, переключатель недоступен и отправка не
  откатывается на локальный LAN backend.

## Приватность и границы

Тело запроса содержит только `{ "type": "..." }`: ни путь к фильму, ни его
название, ни LiveKit JWT, ни invite token в нём нет. Однако URL запроса
содержит ID комнаты, а cookie/Bearer нужен для проверки членства. Поэтому UI
не обещает полной анонимности: сервер пишет только aggregate counter с типом
события, но эксплуатационные access logs reverse proxy требуют отдельной
политики retention и редактирования. Нельзя использовать эти клиентские
счётчики как единственное доказательство готовности сети.

LAN UI и `/api/v1/telemetry` не меняются. Internet mode по умолчанию выключен.
Новых backend routes и контрактов нет — используется SPS-731.

## Проверки

- `pnpm --filter @spectemus-simul/frontend exec vitest run
src/features/internet/connection-telemetry.test.ts
src/features/internet/internet-api.test.ts src/pages/InternetRoomPage.test.tsx`
- `node --test desktop/src/main/device-binding.test.mjs`
- `pnpm check`

Тесты проверяют запрет отправки до согласия, дедупликацию и выключение,
browser cookie path, desktop Bearer/allowlist, отсутствие секретов в теле,
устойчивость просмотра к ошибке телеметрии и отсутствие fallback в LAN.

Следующий gate — настоящая конфигурация VM/DNS/TLS/WSS/TURN, политика access-log
retention и физический прогон между разными сетями. Это не подтверждается
зелёным CI или тестами на одной машине.
