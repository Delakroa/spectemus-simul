# WT-676 — завершение комнаты и повторная публикация видео

## Цель

Сделать переходы в LAN-комнате понятными и предсказуемыми после двух реальных
проверок на Mac и Windows:

- после закрытия комнаты у host-а и guest-а одновременно оставались старая
  панель комнаты, чат и участники рядом с формой создания новой комнаты;
- после «Остановить» и новой публикации видео guest мог временно видеть
  «Нет состояния», хотя host уже снова управлял воспроизведением.

## Реализовано

- Закрытая или истёкшая комната больше не рендерит рабочую поверхность: видео,
  чат, участников, приглашение, отзывы и диагностику.
- Вместо неё оба участника видят один терминальный экран «Комната закрыта» с
  объяснением, что прежняя ссылка и чат больше недоступны, и с обычными
  действиями для новой комнаты или нового приглашения.
- Состояния playback получают монотонный revision на протяжении сессии host-а.
  После остановки новый publisher продолжает счётчик, поэтому guest принимает
  его первое новое `publish`-состояние сразу, а не после десятков heartbeat.
- Для штатной остановки показано человеческое «Остановлено», а не вводящее в
  заблуждение «Нет состояния».

## Поведение продукта

Закрыть комнату может только host. Это завершает текущий просмотр для всех
участников. Новая комната всегда получает новый ID и новую ссылку приглашения:
старое приглашение намеренно не используется повторно, чтобы завершённая
сессия не открылась снова по ошибке.

## Проверка

1. Host и guest входят в одну LAN-комнату.
2. Host нажимает «Закрыть».
3. На обоих устройствах нет старого видео, чата, списка участников и кнопки
   приглашения; есть экран «Комната закрыта» и формы новой комнаты.
4. Host создаёт новую комнату и передаёт гостю её новую ссылку.
5. В отдельной комнате host публикует видео, ставит его на паузу, нажимает
   «Остановить», затем снова публикует и нажимает play/pause. Guest сразу видит
   актуальный статус без временного «Нет состояния».
