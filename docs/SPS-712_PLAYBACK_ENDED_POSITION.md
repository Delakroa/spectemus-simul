# SPS-712 — Ползунок доходит до конца видео

## Проблема

В физическом прогоне Mac ↔ Windows короткое видео уже показывало время
`0:05 / 0:05`, но ползунок оставался немного левее конца. Последнее событие
`timeupdate` могло прийти до фактической длительности, а обработчик `ended`
менял только статус воспроизведения.

Та же неточная позиция уходила гостю в LiveKit data message. Поэтому дефект
мог быть виден как на host, так и в синхронизированном состоянии guest-а.

## Решение

- При `ended` host UI фиксирует `currentTime` ровно на известной длительности
  видео.
- Событие `ended` передаёт гостю ту же конечную позицию, а не значение
  последнего `timeupdate`.
- Если браузер не сообщил конечную длительность, остаётся безопасный fallback
  на последнюю конечную позицию без `NaN` и отрицательных значений.

Семантика обычной перемотки, паузы и heartbeat не меняется.

## Проверка

```bash
pnpm --dir frontend exec vitest run \
  src/features/rooms/use-room-session-host-controls.test.tsx \
  src/features/rooms/playback-state.test.ts
pnpm check
```

Регрессионные тесты отдельно подтверждают конечную позицию в локальном UI
host-а и в сообщении синхронизации для guest-а.

## Ограничения

Исправление относится к позиции после штатного события `ended`. Оно не меняет
поведение повреждённого файла или аварийно оборванного media track.
