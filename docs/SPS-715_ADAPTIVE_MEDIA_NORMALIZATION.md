# SPS-715: адаптивная подготовка MKV и других контейнеров

## Проблема

Desktop host всегда полностью перекодировал любой файл, который не прошёл
надёжный browser-native путь. Это было безопасно, но не учитывало содержимое
контейнера: MKV с уже совместимыми H.264/AAC зря терял время и качество на
повторном кодировании.

## Решение

`ffprobe` определяет не только названия видео- и аудиокодеков, но и pixel format.
На основе результата normalizer выбирает минимально необходимую работу:

| Исходные дорожки                             | Действие                                     |
| -------------------------------------------- | -------------------------------------------- |
| H.264 8-bit `yuv420p` + AAC                  | Быстрый remux в MP4, обе дорожки копируются  |
| H.264 8-bit `yuv420p` + DTS/FLAC/другой звук | Видео копируется, только звук становится AAC |
| HEVC/другое видео + AAC                      | Только видео становится H.264                |
| Несовместимые видео и звук                   | Полная подготовка H.264/AAC                  |

H.264 10-bit намеренно не копируется: поддержка такого профиля в Chromium на
целевых Mac и Windows недостаточно предсказуема. Он проходит через совместимый
8-bit H.264 профиль.

Во всех вариантах создаётся локальный временный MP4. Оригинал не меняется и не
загружается в backend. Итоговая копия повторно проверяется: видео должно быть
H.264, звук при наличии — AAC.

## Проверки

- Unit-тесты планов remux, частичной и полной подготовки.
- Unit-тест защищает от ошибочного копирования H.264 10-bit.
- Оценка свободного места для remux опирается на размер исходного файла, а не на
  полный целевой bitrate перекодирования.
- Реальный локальный smoke: H.264/AAC MKV переложен FFmpeg 8.1.2 в MP4 с
  сохранением кодеков `h264` и `aac`.
- `pnpm check`.

## Ограничения

- MKV — контейнер, а не кодек. HEVC, AV1, DTS, FLAC и экзотические профили всё
  ещё требуют частичной или полной подготовки.
- VLC/mpv воспроизводят больше форматов напрямую, потому что поставляют
  собственный multimedia pipeline. Spectemus должен получить browser-compatible
  поток для `captureStream()` и WebRTC, поэтому полностью отказаться от
  подготовки нельзя.
- Физический прогон длинного MKV на Windows-host остаётся release evidence.
