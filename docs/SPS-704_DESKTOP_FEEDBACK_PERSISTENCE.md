# SPS-704 — сделать канал отзывов desktop host читаемым

## Цель

Отзывы, собранные во время прогона, должны существовать после прогона. Сейчас
канал write-only: форма принимает отзыв и возвращает receipt, но прочитать
собранное невозможно.

Это второй тикет из P1 category-B и предусловие физического прогона Mac ↔
Windows: README называет отзыв способом сообщить о проблеме, а правило прогона
требует заводить отдельный SPS-тикет на каждый найденный дефект. Без исправления
журнал дефектов самого прогона теряется.

## Что было

Две независимые причины давали один результат.

1. **Хранилище только в памяти.** Desktop-профиль использовал `InMemoryFeedbackStore`,
   то есть `Map` внутри процесса. После выхода из приложения отчёты исчезали — а
   оператор открывает «Оператор» уже после сессии.
2. **Operator-эндпоинты отключены.** `spawnBackend` не передавал
   `FEEDBACK_ADMIN_TOKEN`, его значение по умолчанию пустое, поэтому
   `adminEnabled()` возвращал `false` и список/экспорт/triage отвечали
   `403 FEEDBACK_OPERATIONS_DISABLED`.

## Изменения

- `InMemoryFeedbackStore` заменён на `DesktopFeedbackStore`: отчёты
  восстанавливаются при старте и записываются на диск после каждого сохранения.
  Запись идёт через временный файл с атомарной заменой, поэтому обрыв не оставит
  наполовину записанный журнал. Сбой чтения или записи не превращается в ошибку
  пользователю: отзыв уже принят, а повреждённый файл перезапишется следующей
  записью.
- Путь задаётся `spectemus-simul.feedback.storage-path`
  (`FEEDBACK_STORAGE_PATH`). Пустое значение сохраняет прежнее поведение —
  только память, — поэтому тесты и запуски без выделенного каталога не меняются.
- `loadOrCreateInstallationSecrets` выдаёт `feedbackAdminToken` на установку.
  Существующие установки дополняются токеном без перевыпуска LiveKit-секретов.
- `spawnBackend` передаёт backend `FEEDBACK_ADMIN_TOKEN` и `FEEDBACK_STORAGE_PATH`;
  файл лежит в `<userData>/runtime/feedback-reports.json`.

## Как оператору получить отзывы

Оба пути работают после завершения сессии:

- страница «Оператор» — токен берётся из
  `<userData>/runtime/installation-secrets.json`, поле `feedbackAdminToken`;
- либо напрямую файл `<userData>/runtime/feedback-reports.json` — его можно
  приложить к тикету как есть.

## Проверка

```bash
node scripts/run-gradle.mjs :backend:test --no-daemon
node --test desktop/src/main/*.test.mjs
```

Локально: backend BUILD SUCCESSFUL, desktop 45/45.

`DesktopFeedbackStoreTest` проверен откатом: без записи на диск падают и
«переживает перезапуск процесса», и «стартует пустым на повреждённом файле».

## Граница задачи

Токен намеренно не отдаётся в renderer через IPC: это расширило бы права
страницы до admin-доступа к отзывам ради экономии одного копирования. Ротация
токена и UI для неё в задачу не входят.
