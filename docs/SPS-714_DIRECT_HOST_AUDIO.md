# SPS-714: прямой локальный звук для host

## Проблема

На Windows-host звук мог воспроизводиться с перебоями. Host слушал фильм через
дополнительный контур: исходный `<video>` создавал `MediaStream`, а затем видимый
preview повторно воспроизводил этот поток. Такой loopback не нужен для локального
звука и добавляет ещё один realtime-буфер Chromium.

## Реализация

- Локальный звук host-а теперь выводит исходный media element, который читает
  выбранный файл.
- Видимый host preview продолжает показывать захваченный видеопоток, но всегда
  остаётся беззвучным, поэтому второй аудиоконтур не создаётся.
- Громкость и mute host-а применяются к исходному элементу; guest по-прежнему
  управляет своей удалённой аудиодорожкой независимо.
- Настройки повторно применяются после публикации и recovery.

Согласно спецификации Media Capture from DOM Elements, локальные `muted` и
`volume` media element не изменяют звук захваченной дорожки. Поэтому host может
регулировать свою громкость, не приглушая трансляцию для guest-а.

## Проверки

- Host preview привязывается с `muted = true`.
- Управление громкостью изменяет исходный media element, а не preview.
- Интеграционный тест страницы проверяет публикацию двух дорожек, mute и 65%
  громкости на источнике.
- `pnpm check`.

## Граница тикета

Тесты подтверждают маршрутизацию в приложении, но реальную стабильность
аудиодрайвера Windows подтверждает следующий физический прогон Windows-host →
Mac-guest.
