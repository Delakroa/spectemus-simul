# SPS-708 — не терять живую копию при замене файла

## Цель

Выбор нового файла во время активного показа не должен разрывать доступ
гостя к уже опубликованному видео. Найден ревью после закрытия P1
category-B backlog, до которого «закрыт полностью» было сказано преждевременно.

## Что было

Кнопка «Выбрать файл» блокировалась только на время `publishing`/`restarting`
(`isFilePublishing` в `HomePage.tsx`), но не в состоянии `live` — то есть
оставалась кликабельной весь показ. `handleMediaPicker` вызывает
`window.spectemusDesktop.pickMediaFile()` напрямую, до того как
`roomSession.selectDesktopMedia` успевает остановить текущую публикацию. На
main-процессе `spectemus:pick-media-file` сразу вызывает
`mediaLibrary.registerSource(...)`, а тот (после SPS-705) начинается с
`await this.clear()` — освобождения всех прежних записей, включая ту, что
gateway прямо сейчас отдаёт гостю по range-запросам. Итог: выбор другого
файла во время просмотра рвал доступ к уже идущей трансляции раньше, чем
кто-либо успевал её остановить.

## Изменения

- Кнопка «Выбрать файл» теперь блокируется и в состоянии `live`
  (`canStopFilePublication`, которое уже объединяет `publishing` /
  `restarting` / `live` для симметричной кнопки «Остановить»), с подсказкой
  «Сначала остановите показ, чтобы выбрать другой файл.».
- `handleMediaPicker` дополнительно проверяет то же условие перед вызовом
  `desktop.pickMediaFile()` — defense in depth на случай гонки (двойной клик,
  программный вызов), а не только полагание на атрибут `disabled`.

## Граница задачи

Основная причина дефекта — main-процесс не знает о состоянии публикации:
`DesktopMediaLibrary.registerSource` очищает прежние записи независимо от
того, смотрит ли их сейчас гость. Настоящая защита на этом уровне потребовала
бы протащить статус публикации через IPC в `mediaLibrary`, что расширило бы
эту задачу далеко за пределы «небольшого тикета». Текущий фикс закрывает
единственный путь, которым renderer может инициировать замену файла — кнопку
picker, — поэтому пользователь физически не может запустить сценарий через
штатный UI. Если в будущем появится второй способ выбрать файл в desktop
runtime, потребуется отдельная защита на уровне `mediaLibrary`.
