# SPS-737 — локальный proof сжатых сегментов

## Цель

Проверить гипотезу из SPS-736: для совместимого локального фильма можно не
выполнять live-захват и повторное кодирование каждого кадра. Host делает remux,
а guest получает сжатые блоки и сам декодирует видео через MSE. Это первый
узкий media-proof, **не** закрытие первоначального сетевого gate SPS-737.

## Область

Отдельный `poc/host-segments`, без новых зависимостей и без изменений product
API/контрактов. Single-pair signaling работает на компьютере host-а только на
loopback. Два capability по 256 bit передаются в URL fragment, извлекаются в
память и убираются из адресной строки. Файл читается локальной PoC-службой;
он не загружается в application backend и недоступен guest через HTTP.
Полученные через DataChannel фрагменты гость может сохранить/собрать: это
не DRM и не защита от копирования доверенным участником.

Signaling проверяет Origin/Host, роли и размеры payload; binary media на нём
запрещены. Есть bounded range-чтение до 64 KiB, backpressure после MSE append,
отмена и очистка при обычном выходе. Это защита локального эксперимента, не
аудированная схема публичного приглашения.

## Запуск и evidence

См. [README прототипа](../poc/host-segments/README.md). Основные команды:

```bash
pnpm segment:poc -- --input <H264-AAC-file>
pnpm test:media-poc
pnpm segment:poc:smoke
pnpm check
```

Фактический прогон на этой машине (Chrome, два независимых context, синтетический
24-секундный H.264/AAC MKV):

- stream-copy remux: 70–74 мс в двух успешных прогонах; итоговый fMP4 — 6 128 856 байт;
- на паузе получено 3 080 192 байта и 12,02 с запаса, а не весь файл;
- guest дошёл до 24,021 с, декодировал 720 кадров и 216 119 audio bytes;
- pause/resume, natural ended, отсутствие page errors и освобождение MediaSource
  после stop подтверждены; новый boundary suite — 12/12;
- финальный `pnpm check` прошёл, включая существующие product/LAN тесты и сборки.

Прогон использует **test-only замену ICE host candidates на loopback** в smoke,
не в UI. Это настоящие DataChannel/DTLS/SCTP и MSE, но не proof native ICE.
Нативный ICE этой среды не прошёл даже в минимальном тесте без media: есть
кандидаты, но нет ответов; UDP доставлялся на `127.0.0.1`, но не на собственные
LAN-адреса. Причина политики/маршрутизации среды не установлена и не маскируется
под исправленную проблему. Настройки сети не менялись.

Физическая загрузка CPU/GPU/полной RAM и слышимый звук пока не измерены.

ресурсы с текущим capture/LiveKit pipeline; отдельно проверить путь до браузера
