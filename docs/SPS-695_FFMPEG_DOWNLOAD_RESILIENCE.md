# SPS-695 — устойчивая и доверенная загрузка FFmpeg

## Цель

FFmpeg скачивается и собирается из исходников при каждой сборке desktop-инсталлятора.
Шаг загрузки был одновременно хрупким (сетевой сбой ронял сборку) и не давал
независимой гарантии подлинности архива.

## Изменения

### Закреплённый отпечаток ключа подписи

Публичный ключ и архив изначально забирались с того же хоста (`ffmpeg.org`).
Поэтому сама по себе проверка подписи ничего не гарантировала: хост, отдавший
подменённый архив, отдал бы и подходящий к нему ключ — проверка замыкалась сама
на себя. SPS-699 закрепил открытую часть ключа в репозитории и убрал сетевую
загрузку ключа из installer: временная недоступность endpoint больше не может
сорвать проверку уже известного trust root.

Теперь отпечаток закреплён в скрипте, и после импорта проверяется, что в keyring
именно он:

```
FCF986EA15E6E293A5644F10B4322F04D67658D8
```

Последние 16 символов — `B4322F04D67658D8` — общеизвестный key id релизного ключа
FFmpeg, поэтому значение сверяемо с публичными источниками, а не принято на веру.
При несовпадении сборка останавливается до распаковки архива.

### Изолированный keyring

Проверка выполняется во временном `GNUPGHOME` внутри рабочего каталога. Раньше
ключ импортировался в keyring пользователя: на переиспользуемом runner результат
зависел от посторонних ключей, а сам keyring засорялся. Каталог удаляется общим
`cleanup`.

Поскольку keyring содержит только проверенный ключ, успешная проверка подписи
означает, что архив подписан именно им.

### Общий лимит времени загрузки

К `--connect-timeout` добавлен `--max-time`. Соединение может установиться и затем
встать: без общего лимита job висел до собственного таймаута в 35 минут вместо
того, чтобы упасть и уйти на повтор.

## Проверка

```bash
bash -n scripts/build-media-sidecar.sh
node --test scripts/build-media-sidecar.test.mjs
```

`build-media-sidecar.test.mjs` запускает скрипт с подставными `curl` и `gpg` в
начале `PATH` и проверяет поведение, а не текст: при чужом отпечатке сборка
останавливается с внятной ошибкой до распаковки, при совпадающем — проходит
проверку ключа дальше. Отдельный тест имитирует `curl (35)`: первая попытка
оставляет неполный файл, вторая завершается успехом; в итоговый путь попадает
только полный файл, а `.partial` удаляется.

## Граница задачи

Зеркало для архива намеренно не добавлено: у альтернативных источников нет
подписи `.asc`, и переключение на них ослабило бы проверку подлинности ради
доступности. Логика повторов и атомарная запись через `.partial` не менялись.
