# SPS-710 — не разрывать WebSocket комнаты по таймауту gateway

## Цель

Соединение комнаты должно оставаться открытым между heartbeat-сообщениями. Во
время физического прогона Mac ↔ Windows участники циклически переходили в
`offline` и обратно в `online` примерно каждые 15 секунд.

## Причина

Gateway устанавливал для upstream WebSocket тот же 15-секундный таймаут, который
используется для коротких HTTP-запросов. Таймаут оставался активным после
успешного ответа `101 Switching Protocols`. Клиент комнаты отправляет heartbeat
тоже раз в 15 секунд, поэтому gateway мог закрыть исправный туннель непосредственно
перед следующим heartbeat.

## Изменения

- таймаут upstream WebSocket теперь ограничивает только установку соединения;
- после первого ответа backend таймаут отключается, а живость участника продолжает
  определяться штатным heartbeat комнаты;
- длительность handshake-timeout можно уменьшить в тесте без изменения безопасного
  значения runtime;
- регрессионный тест удерживает установленный туннель без данных дольше таймаута и
  затем проверяет прохождение сообщения от backend.

## Проверка

```bash
node --test desktop/src/main/gateway.test.mjs
node --test desktop/src/main/*.test.mjs
```

Физическая проверка после новой сборки: Mac и Windows должны оставаться `online`
дольше минуты без чередования событий `participant.offline` / `participant.online`.

## Граница задачи

Алгоритм presence и 15-секундный интервал heartbeat не менялись. HTTP upstream
timeout также остаётся прежним. Задача исправляет только ошибочный idle-timeout
уже установленного WebSocket-туннеля.
