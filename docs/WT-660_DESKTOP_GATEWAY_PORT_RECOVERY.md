# WT-660 — восстановление desktop gateway при занятом порте

## Проблема

Desktop host всегда пытался открыть LAN gateway на `0.0.0.0:8088`. Если на
компьютере уже работал development gateway или другое приложение, Electron
показывал технический `EADDRINUSE`, хотя собственные backend и LiveKit могли
уже успешно стартовать. Пользователь не мог создать комнату.

## Решение

1. Gateway сначала пытается использовать привычный `8088`.
2. При системной ошибке `EADDRINUSE` существующий процесс не останавливается и
   не переподключается.
3. Gateway повторно запускается с TCP-портом `0`; ОС выбирает свободный порт.
4. Фактический порт входит в local URL Electron и в `window.location.origin`,
   поэтому invite-ссылка, QR-код и копирование ссылки передают гостю правильный
   адрес.
5. Навигация в Electron разрешена только на фактический loopback origin, а не
   на жёстко заданный `127.0.0.1:8088`.

## Проверка

```bash
pnpm --dir desktop test
```

Тесты проверяют normal path на `8088`, fallback после `EADDRINUSE` и то, что
любая другая ошибка запуска не скрывается fallback-логикой.

## Ограничения

- Это исправление относится к HTTP gateway. Конфликты портов backend или
  LiveKit остаются явной ошибкой запуска: их нельзя автоматически заменить
  одним портом, потому что они затрагивают связанный TCP/UDP media runtime.
- Ручной ввод адреса должен использовать порт из выданной invite-ссылки, а не
  предполагать `8088`.
