# SPS-733 — приватность журналов публичного gateway

## Цель и граница

Не сохранять URL Internet-комнат и одноразовые параметры в журналах публичного
Nginx gateway. Меняется только opt-in staging gateway. LAN gateway, backend,
LiveKit и внешний Caddy этим тикетом не переконфигурируются.

## Решение

На уровне публичного `server` выключены `access_log` и `error_log`. Одного
выключения access log недостаточно: ошибка upstream может записать в error log
полную строку запроса. Ошибки запуска Nginx на глобальном уровне остаются
доступны, но диагностика отдельных запросов на этом gateway намеренно
ограничена. Для анализа межсетевых сбоев используются добровольные
агрегированные события SPS-731/732 и локальный отчёт SPS-730.
Директивы и их области действия сверены с официальными разделами Nginx про
[access_log](https://nginx.org/en/docs/http/ngx_http_log_module.html) и
[error_log](https://nginx.org/en/docs/ngx_core_module.html).

Это не гарантирует приватность всего стенда: Caddy, LiveKit, backend и Docker
могут вести собственные журналы. Перед открытием доступа оператор обязан
проверить настройки этих сервисов на реальной VM, выключить или редактировать
HTTP access logs, исключить URL, query, cookie, Authorization и адрес клиента,
ограничить доступ и срок хранения. Проверка записана в
`infra/staging/README.md`; без неё gate остаётся открытым.

## Проверка и откат

```bash
pnpm test:staging
docker compose --env-file <protected-env> \
  -f infra/staging/compose.yaml -f infra/staging/public.compose.yaml config --quiet
pnpm check
```

Регрессионный тест проверяет настройки именно публичного server-блока, чтобы
`access_log off` у внутреннего healthcheck не давал ложный успех. На реальной VM
следует проверить журналы после запросов с тестовым URL без настоящих токенов.
Результат локальных тестов не подтверждает конфигурацию Caddy и LiveKit.

Откат — вернуть прежний `public-gateway.conf` только вместе с осознанной
альтернативной политикой редактирования логов; простой откат снова разрешит
запись потенциально чувствительных URL.
