# SPS-697 — восстановление загрузки подписи FFmpeg

## Факт прогона

Preview installer-run `31248804407` подтвердил работу SPS-695 частично: Windows
дважды получил `curl (35)` при загрузке архива FFmpeg и успешно скачал его на
третьей попытке. Затем сервер `ffmpeg.org` не отдал маленький файл подписи
`.asc`: пять попыток закончились `curl (28)` или `curl (35)`.

Лог выявил второй дефект: после ожидаемого отказа `EXIT`-trap писал
`work_directory: unbound variable`, потому что обращался к `local` переменной
после возврата из `main`.

## Изменения

- Число попыток увеличено с 5 до 7. После каждой неудачи пауза растёт
  экспоненциально: 5, 10, 20, 40, затем не более 60 секунд. Лимиты задаются
  переменными окружения для CI и тестов.
- `connect-timeout` увеличен с 20 до 60 секунд: медленное установление
  соединения с официальным сервером не считается немедленной ошибкой.
- `.partial` и проверка закреплённого ключа из SPS-695 сохранены: усиление
  доступности не ослабляет доверие к архиву.
- Cleanup получает путь при установке `EXIT`-trap, а не читает пропавшую local
  переменную после завершения `main`.

## Проверка

Тесты имитируют две ошибки `curl (35)` и успешную третью попытку, проверяя
последовательность пауз `2`, `4`. Проверка чужого fingerprint теперь также
гарантирует отсутствие `unbound variable` при cleanup.

## Граница

Зеркало подписи не добавляется: источник подписи должен оставаться официальным
FFmpeg endpoint, иначе доступность могла бы подменить проверяемость.
