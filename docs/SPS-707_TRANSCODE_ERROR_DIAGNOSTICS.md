# SPS-707 — диагностировать ошибку транскода

## Цель

Сбой подготовки видео должен превращаться в тикет с точной причиной, а не в
общую фразу «что-то пошло не так». Пятый, последний тикет из P1 category-B,
закрывает B1.

## Что было

- `ipcMain.handle` по умолчанию отдаёт renderer-у только `error.message` —
  `MediaNormalizationFailure.code` терялся на границе IPC, и `use-room-session.ts`
  видел обычный `Error` без возможности различить причины программно.
- stderr ffmpeg собирался (последние 4000 символов) только для построения
  текста ошибки и нигде не сохранялся — после того как сообщение показано и
  забыто, восстановить причину падения было нечем.
- `describeTranscodeFailure` матчила «Unknown encoder» / «Error while opening
  encoder» / «Cannot create compression session» в один и тот же текст про
  видеокодек, хотя та же группа паттернов срабатывает и при отказе AAC-энкодера
  на выходном audio stream — дефект уходил не в ту подсистему.

## Изменения

- `classifyTranscodeStderr(stderr, videoEncoder)` — различает
  `VIDEO_ENCODER_FAILED` и `AUDIO_ENCODER_FAILED` по индексу output stream в
  сообщении ffmpeg (`-map 0:v:0` → `#0:0`, `-map 0:a:0?` → `#0:1`) и по имени
  энкодера; остальное остаётся `TRANSCODE_FAILED`.
- `persistTranscodeDiagnostics(...)` — при провале транскода сохраняет полный
  захваченный stderr в `<userData>/logs/ffmpeg-normalize-<uuid>.log`, тот же
  каталог, что уже используют логи backend и LiveKit сайдкаров. Путь
  подставляется в текст ошибки, так что сообщение из отзыва уже указывает,
  какой файл приложить к тикету. Запись — best-effort и не блокирует основную
  ошибку: если каталог логов недоступен на запись, оператор всё равно получает
  понятный текст.
- `DesktopMediaNormalizer` принимает `logDirectory`; `main.mjs` передаёт уже
  существующий `sidecarLogDirectory` (`<userData>/logs`).

## Граница задачи

`error.code` по-прежнему не пересекает границу IPC как отдельное поле —
Electron прокидывает только `message`. Это не исправлено, потому что после
этого тикета не осталось ни одного потребителя, которому нужен именно код:
текст ошибки уже называет причину и путь к диагностике, а `use-room-session.ts`
показывает пользователю сообщение целиком. Если в будущем понадобится
программная ветвление по коду на фронтенде — потребуется отдельная схема
сериализации ошибок через IPC, здесь она не вводится.

## Проверка

```bash
node --test desktop/src/main/*.test.mjs
```

Локально: desktop 54/54 (два новых теста).

Оба новых теста проверены откатом: без разбора stderr по индексу output stream
`classifyTranscodeStderr` тестового ассерта не проходит и всегда возвращает
`TRANSCODE_FAILED`, а без вызова `persistTranscodeDiagnostics` интеграционный
тест не находит файл диагностики в `logDirectory`.
