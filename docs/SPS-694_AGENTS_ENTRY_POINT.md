# SPS-694 — AGENTS.md как точка входа без дублей

## Цель

Убрать второй источник правил. `AGENTS.md` пересказывал `docs/CONVENTIONS.md`
(границы подсистем, приватность, контракты, стиль backend/frontend, порядок
документирования). Две копии одних правил расходятся со временем, и агент
начинает работать по устаревшей.

## Изменения

- `AGENTS.md` сокращён до карты проекта, таблицы «где искать правила» и раздела
  про работу самого агента. Пересказ конвенций удалён.
- `docs/CONVENTIONS.md` дополнен тем, что раньше существовало только в
  `AGENTS.md`:
  - в «Границы репозитория» добавлены `desktop/`, `contracts/`, `e2e/`;
  - в «Команды» описано, что списки prettier разбиты по темам (`format:check`,
    `format:installer`, `format:lan`, `format:staging`, `format:media-poc`,
    `format:media-compatibility`) и новый документ нужно дописать в цепочку своих
    соседей, иначе CI не проверит форматирование.
- В `AGENTS.md` оставлены только правила, которых нет в других документах:
  ветка заводится до начала правок, коммит и push выполняет владелец
  репозитория, нельзя сообщать о непройденной проверке как о пройденной, нужно
  проверять состав коммита, каждое изменение сопровождается отчётом и попадает в
  цепочку `format:*`.
- `AGENTS.md` добавлен в `format:check`, чтобы его форматирование тоже
  проверялось.

## Проверка

```bash
node_modules/.bin/prettier --check AGENTS.md docs/CONVENTIONS.md
```

Дублей проверяемо не осталось: правила из `AGENTS.md` теперь либо ссылаются на
`docs/CONVENTIONS.md` и `docs/DEFINITION_OF_DONE.md`, либо не встречаются больше
нигде.

## Граница задачи

Смысл конвенций не менялся — только их местоположение. Историю правил и отчёты
`WT-*` изменение не затрагивает.
