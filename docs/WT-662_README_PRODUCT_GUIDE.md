# WT-662 — Публичное руководство в README

## Цель

Сделать корневой README понятной первой страницей Spectemus Simul для человека,
который хочет посмотреть свой фильм вместе с другим человеком. Ранее в нём
смешивались реклама продукта, команды разработки и внутренняя хронология из
десятков тикетов. Такой текст не помогал ни установить приложение, ни понять
реальные ограничения preview.

## Решение

Корневой README теперь отвечает только на пользовательские вопросы:

1. Что делает продукт и чем он не является.
2. Для какого сценария подходит текущая LAN preview.
3. Как выбрать, скачать и установить artifact для macOS Apple Silicon, macOS
   Intel или Windows x64.
4. Как host создаёт комнату, а guest подключается по полной invite-ссылке.
5. Какие форматы являются базовыми, а какие — экспериментальными.
6. Какие ограничения и действия при типичных проблемах честно известны сейчас.

История P0–P9, список тикетов, контракты и архитектурные решения остаются в
`docs/`. Корневой README ссылается на эту папку только в разделе для
разработчиков.

## Фактические продуктовые границы, отражённые в тексте

- Сейчас это LAN-first desktop preview: host и guest находятся в одной домашней
  сети; режим между разными городами ещё не выпущен.
- Host использует desktop-приложение. Guest открывает invite в desktop
  Chrome/Edge и не устанавливает приложение.
- Оригинальный файл не загружается и не хранится приложением, но медиапоток
  передаётся гостю по сети. Нельзя называть это защитой от записи экрана.
- MP4/M4V H.264 + AAC и WebM VP8/VP9 + Opus — заявленный baseline. Остальные
  контейнеры допускаются только после реальной decode/capture проверки на
  устройстве host-а.
- Preview installers unsigned, artifacts GitHub Actions хранятся 14 дней; до
  signed release пользователь должен осознанно подтвердить установку.
- Голос в LAN HTTP preview может быть недоступен из-за browser secure-context
  policy. Видео и текстовый чат не зависят от этого ограничения.

## Проверка

```bash
pnpm format:check
git diff --check
```

Ручная проверка текста:

1. Человек без знания репозитория может выбрать свой artifact и пройти
   установку, не читая внутренние тикеты.
2. Инструкция не требует Docker, Node.js или ручного выбора TCP-порта для
   готовой desktop preview.
3. Установка и первый просмотр не дают ложного обещания поддержки любого
   видеофайла, работы через интернет или подписанного релиза.

## Следующий шаг

Когда появится подписанный release, в README нужно заменить временный путь
через GitHub Actions на стабильную ссылку Releases и убрать инструкцию по
обходу карантина для unsigned preview. Это отдельная release-задача: текст
нельзя менять раньше, чем появятся реальные signed/notarized installers.
