# WT-684 — устойчивость desktop runtime к закрытию окна и сетевым сбоям

## Цель

Desktop host должен останавливаться полностью, даже если пользователь закрыл окно
во время просмотра. Ошибка одного устройства в домашней сети или одного
оборванного WebSocket-соединения не должна останавливать host или лишать других
участников событий комнаты.

## Что сделано

### Жизненный цикл desktop host

- После закрытия окна ссылка на него очищается. Отправка статуса и попытка
  вернуть фокус сначала проверяют, что окно ещё существует.
- Ошибка UI-подписчика статуса изолирована: она не может оборвать остановку
  gateway, backend или LiveKit.
- Повторный `Cmd+Q`/выход ждёт уже начатую очистку, а не завершает Electron до
  неё. Только после остановки sidecar-процессов и освобождения выбранного видео
  приложению разрешается выйти.
- При старте удаляется только собственная временная папка нормализованных MP4.
  Так аварийное завершение не оставляет на диске старые многогигабайтные копии.

### LAN gateway и подготовка видео

- Некорректный HTTP или WebSocket request target получает `400 Bad Request` и
  не завершает процесс host-а.
- Обрыв range-запроса гостем уничтожает исходный file stream. Перемотка видео
  не накапливает файловые дескрипторы.
- Пустой видеофайл отвечает корректно: без `Range` — пустым `200`, с `Range` —
  `416`, без падения `createReadStream`.
- `ffprobe` учитывает отмену и имеет ограничение времени. При отмене или
  зависании процесс сначала получает `SIGTERM`, затем при необходимости
  `SIGKILL`; временный output удаляется.

### Устойчивость комнаты и права LiveKit

- Токен гостя сохраняет публикацию data packets и микрофона, но ограничивает
  источники публикации `microphone`. Host по-прежнему может публиковать фильм и
  звук.
- Ошибка отправки одному WebSocket-получателю изолирована. Остальные участники
  продолжают получать события `participant.*`, чат и закрытие комнаты.
- Потеря LiveKit в момент очередного playback heartbeat не оставляет
  `unhandled rejection` в браузере; следующее состояние будет опубликовано при
  восстановлении соединения.

## Проверки

- Node unit tests: shutdown coordinator, media normalizer, DesktopSupervisor и
  LAN gateway, включая malformed URL, пустой файл и обрыв media-запроса.
- Backend tests: подписи host/guest LiveKit JWT и продолжение WebSocket fan-out
  после `IOException` одного получателя.
- Frontend test: отклонённый `publishData` не создаёт необработанное promise
  rejection.

## Граница

Это hardening LAN desktop preview. Он не делает приложение публичным
интернет-сервисом: Internet mode остаётся отдельной стадией с TLS, TURN,
аккаунтами и приглашениями из [PRODUCT_ROADMAP.md](PRODUCT_ROADMAP.md).
