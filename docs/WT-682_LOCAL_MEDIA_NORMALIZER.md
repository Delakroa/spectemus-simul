# WT-682 — Local media normalizer

## Цель

Сделать просмотр распространённых локальных видеофайлов предсказуемее для
desktop host-а. Базовые MP4/M4V и WebM могут идти напрямую, а контейнеры вне
этого пути (например, MKV) заранее готовятся в локальную MP4-копию с H.264/AAC.
Это закрывает типичный случай MKV с HEVC или DTS: оригинальный файл остаётся у
host-а, а гостям передаётся только совместимый медиа-поток.

## Что реализовано

- В desktop-приложении кнопка выбора фильма открывает системный file picker.
  В renderer не передаётся абсолютный путь к файлу.
- Базовые MP4/M4V и WebM сначала проходят быстрый direct path: Chromium
  проверяет файл и, если может его декодировать и отдать через `captureStream()`,
  фильм публикуется без перекодирования.
- Для экспериментальных контейнеров и при неудачной decode/capture проверке
  desktop host локально запускает bundled FFmpeg. UI показывает подготовку в
  процентах и даёт отменить её.
- Перед подготовкой `ffprobe` определяет кодеки и pixel format. Совместимые
  H.264 8-bit/AAC дорожки быстро перекладываются в MP4 без перекодирования;
  если несовместима только одна дорожка, перекодируется только она. Для
  остальных файлов на macOS используется `h264_videotoolbox`, на Windows —
  `h264_mf`, а несовместимый звук приводится к AAC. Выход проверяется через
  `ffprobe`: видео обязано быть H.264, аудио (если есть) — AAC.
- Временный MP4 хранится в temporary directory приложения, используется только
  host Chromium через `/_desktop/media/<random-id>` на loopback и удаляется
  при новом выборе фильма, выходе/закрытии комнаты или завершении приложения.
  Gateway отклоняет этот endpoint для LAN-клиентов, поэтому guest не может
  скачать исходный фильм или временную копию.
- Installer workflow собирает FFmpeg 8.1.2 из официального подписанного source
  archive без `--enable-gpl` и `--enable-nonfree`, динамически линкует libraries
  и добавляет source archive, signature, configure line и LGPL notice к
  download artifact.

## Как проверить

1. Скачайте свежий desktop installer artifact с зелёного запуска `Desktop
installer`.
2. Создайте комнату в приложении host-а и выберите MP4, затем MKV HEVC/AAC или
   MKV H.264/DTS, которыми вы вправе пользоваться.
3. Для базового MP4 или WebM убедитесь, что публикация начинается сразу. Для
   MKV и других контейнеров дождитесь «Подготавливаем совместимую копию», затем
   статуса готовности.
4. Подключите guest в той же сети. Проверьте изображение, звук, паузу,
   перемотку и не менее десяти минут просмотра.
5. Остановите показ или закройте комнату. Повторно открыть временную ссылку
   невозможно, а оригинальный файл остаётся на месте и без изменений.

Автоматически проверяются media-library privacy boundary, cancellation/profile
logic normalizer-а, Range-serving loopback gateway, packaging preflight и
наличие FFmpeg/FFprobe в установленном приложении. Реальная матрица длительных
фильмов Mac ↔ Windows остаётся обязательным release evidence.

## Границы и риски

- Это не обещание «любой файл». Защищённые DRM-видео, повреждённые файлы,
  экзотические codecs и компьютеры без доступного системного H.264 encoder-а
  получат понятную ошибку; оригинал не будет отправлен куда-либо.
- Подготовка требует времени CPU/GPU и свободного места под временную копию.
  Файл не загружается на backend, в LiveKit и не попадает в feedback/telemetry.
- Windows Media Foundation и Apple VideoToolbox должны быть проверены на
  реальных supported hosts до заявления о гарантии HEVC/DTS. Если один из
  encoder-ов недоступен, приложение не использует GPL fallback вроде `libx264`.
- Распространение FFmpeg требует сохранять source archive, build notice и LGPL
  notice рядом с installer artifact. До публичного коммерческого релиза нужен
  отдельный legal/patent review H.264 для целевых стран.

## Следующий шаг

После успешных реальных Mac/Windows прогонов зафиксировать compatibility
matrix по codec-ам и только затем переводить Internet room в alpha. Удалённый
режим будет использовать тот же host-side media pipeline: фильм не станет
облачной загрузкой.
