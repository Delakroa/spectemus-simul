# WT-689 — завершение локальных действий воспроизведения

## Цель

Не оставлять host-а с визуально зависшим seek-баром и не блокировать входную
форму комнаты после того, как пользователь закрыл или сменил страницу во время
восстановления сессии.

## Что сделано

- Когда браузер не прислал событие `seeked` за 1,5 секунды, контроллер seek
  освобождает очередь **и** подтверждает последнее действие интерфейсу.
  Значение seek-бар больше не остаётся навсегда в промежуточном состоянии.
- Автоматическое восстановление комнаты по URL теперь снимает
  `pendingAction: restore`, если пользователь уходит с маршрута до ответа API.
  Форма не остаётся отключённой и не показывает вечную загрузку.

## Что уже было закрыто

Проверка также подтвердила прежние исправления: host preview применяет общий
mute/volume state, а очередь быстрых seek хранит только последнее положение и
имеет 1,5-секундный timeout. Поэтому в этот тикет не добавлялись дублирующие
изменения.

## Проверки

```bash
pnpm --filter @spectemus-simul/frontend exec vitest run \
  src/features/rooms/host-seek-controller.test.ts \
  src/features/rooms/use-room-session.test.tsx
pnpm check:ci
```

Тесты фиксируют callback последнего seek по timeout и отмену route restore до
ответа backend-а.

## Граница

Это улучшает реакцию интерфейса локальной комнаты. Guest всё ещё видит
live-stream, а не исходный VOD-файл, поэтому точная перемотка guest-а к
`currentTime` host-а не является целью этого тикета.
