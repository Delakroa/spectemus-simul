# WT-690 — фактический статус roadmap перед Internet mode

## Цель

Привести roadmap к реальному состоянию проекта, чтобы «следующая задача»
означала настоящий продуктовый gate, а не уже слитую техническую работу.

## Зафиксированное состояние

- WT-682 и последующие WT-684–WT-689 завершили repo-side стабилизацию LAN
  desktop preview: local normalizer, lifecycle sidecars, gateway, session
  consistency и конечные состояния интерфейса.
- WT-654 реализован как изолированный, fail-closed public access foundation.
  Он выключен по умолчанию и пока не даёт Internet-room или public media token.
- Режим просмотра из разных городов остаётся запланированным WT-655, а не
  скрытой возможностью текущей LAN-ссылки.

## Ближайший gate

Нужно записать физический Mac ↔ Windows прогон на свежих desktop preview:

1. MP4 H.264/AAC и WebM — publish, видео, звук, play/pause/seek, chat,
   reconnect не менее десяти минут.
2. MKV H.264/AAC, MKV HEVC/AAC и MKV H.264/DTS — локальная подготовка,
   результат на host и guest, удаление временной копии после завершения.
3. Любой дефект из этого прогона сначала становится отдельным LAN-тикетом.

Только успешный evidence позволяет переходить к WT-655.

## Внешняя граница WT-655

Internet room потребует согласованных PostgreSQL, SMTP/sender domain, VM,
трёх DNS-имён, TLS и TURN. Они не создаются репозиторием и требуют решения
владельца продукта по поставщику, региону, оплате и доступу администратора.
После появления этих ресурсов WT-655 реализует отдельный Internet mode, а
WT-656 докажет сессию «host дома → guest в другом городе».
