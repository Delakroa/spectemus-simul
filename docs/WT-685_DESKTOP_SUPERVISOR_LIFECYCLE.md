# WT-685 — lifecycle desktop supervisor

## Цель

Сделать запуск и остановку desktop host последовательными: выход из приложения
во время preflight не должен создавать новые sidecar-процессы, а поздно открытый
gateway не должен остаться доступным в домашней сети без host-а.

## Что сделано

- Перед recovery старых sidecar-процессов supervisor переходит в состояние
  запуска. Остановка в этот момент помечает старт прерванным; после окончания
  recovery дальнейший preflight и запуск backend/LiveKit не выполняются.
- После асинхронного запуска gateway supervisor повторно проверяет состояние.
  Если backend или LiveKit уже остановили сессию, новый gateway закрывается до
  присвоения в runtime и не остаётся слушать LAN-порт.
- `stopChild` распознаёт завершение дочернего процесса по `signalCode`, а не
  только по `exitCode`. Обычное завершение по сигналу не создаёт ложный статус
  «потребовала принудительного завершения» и не мешает очистке ownership record.
- Recovery старых подтверждённых процессов сначала ждёт штатный `SIGTERM`, а
  затем отправляет `SIGKILL`. Если процесс всё равно не подтверждает выход,
  ownership record сохраняется для следующей безопасной попытки, а новый host
  не стартует рядом с потенциальным сиротой.

## Проверки

- Остановка во время recovery не вызывает `spawnBackend` или `spawnLiveKit`.
- Аварийный выход LiveKit во время `startGatewayWithFallback` закрывает
  полученный позднее gateway.
- Процесс, завершённый сигналом, корректно считается остановленным.
- Recovery проверяет команду процесса, применяет `SIGTERM → SIGKILL` и очищает
  record только после подтверждённого завершения.

## Граница

Задача закрывает только управление процессами desktop host-а. Она не меняет
LAN invite, медиапуть или будущий Internet mode.
