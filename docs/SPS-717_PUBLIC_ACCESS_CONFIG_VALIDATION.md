# SPS-717 — проверка неполной public-access конфигурации

## Проблема

`PublicAccessProperties` должен остановить запуск, если Internet access включён,
а JDBC, pepper, Secure cookie или SMTP не заданы. Проверка вызывала
`isEnabled()` из compact constructor записи. Поле записи присваивается только
после этого тела, поэтому метод видел значение по умолчанию и проверка не
срабатывала. Включённая, но пустая конфигурация создавала объект вместо отказа.

## Решение

В конструкторе проверяется параметр `enabled`, а не поле записи. Неполный
набор настроек по-прежнему выбрасывает `IllegalArgumentException` до появления
маршрутов. Выключенный public access по-прежнему стартует без PostgreSQL и
SMTP. LAN `/api/v1` не меняется.

## Проверки

`pnpm check` завершился успешно.

- backend: 133 теста, включая 4 проверки `PublicAccessProperties`
- frontend: 148 тестов
- desktop: 58 тестов

До исправления те же 4 проверки падали: конструктор не выбрасывал исключение.

## Вне тикета

Выбор Internet room, `/join`, LiveKit token и публичный deploy остаются в
других тикетах. Этот дефект не смешивается с SPS-716.
